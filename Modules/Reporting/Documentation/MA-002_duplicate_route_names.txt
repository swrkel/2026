MA-002 - DUPLICATE ROUTE NAMES : THE REMAINING BLOCKER FOR route:cache
======================================================================

WHY THIS MATTERS
  php artisan route:cache fails with:
      Unable to prepare route [x] for serialization.
      Another route has already been assigned name [y].

  Laravel TOLERATES duplicate route names at runtime - the last one
  registered simply wins - but it REFUSES to cache them, because a cache
  is a name-to-route map and a name cannot point at two routes.

  fully-qualified route names declared : 4,307
  names used more than once            : 280

I FIXED TWO OF THEM ALREADY - see Manufacturing and PriceChanges. Both
used Route::resource('/') which, having no uri to derive from, generated
the bare names index/create/store/show/edit/update/destroy. Naming them
explicitly changed no url and nothing referenced the old bare names.

======================================================================
HOW I WOULD FIX IT
======================================================================

  The safe way is NOT to rename individual routes - every route('name')
  reference would have to move with it, and there are thousands.

  It is to give each module's route group a name prefix it does not
  currently have, so 'dashboard' becomes 'stocktakingnew.dashboard' and
  so on. That is one line per route file, but every reference to the old
  name inside that module must change with it.

  Roughly 30 modules are involved. It is a day's careful work and it must
  be done module by module with the references checked each time - which
  is exactly the kind of change that should not be rushed alongside a
  speed fix.

  MEANWHILE: do NOT run php artisan route:cache. It will fail and leave
  you no worse off, but it will not help either.
