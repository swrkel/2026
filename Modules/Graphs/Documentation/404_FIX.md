# Graphs 404 Fix

## Cause found in the supplied latest application

The host has Nwidart module discovery caching enabled in `config/modules.php`.
Working enabled modules have a module-provider manifest in `bootstrap/cache/*_module.php`.
The first Graphs parcel did not include `bootstrap/cache/graphs_module.php`, so on this
installation the Graphs folder could be present and enabled while its service provider
was not booted. In that state `/graphs` is not registered and Laravel returns 404.

## Fix in this parcel

- Adds `bootstrap/cache/graphs_module.php` for the Graphs providers.
- Adds `Modules/Graphs/Providers/RouteServiceProvider.php`.
- Keeps direct route registration in `GraphsServiceProvider` as a fallback.
- Uses the ERP's normal tenant/session middleware order.
- Does not edit AppServiceProvider, core routes, sidebar Blade files, Petro, POS,
  Products, Finance, or any other existing module.

## Deploy

Extract this ZIP at the Laravel root, preserving paths, then run:

```bash
cd /home/nivasa/public_html
php artisan module:enable Graphs
php artisan optimize:clear
php artisan route:list --name=graphs
```

Expected route names include:

- `graphs.index`
- `graphs.data.tanks`
- `graphs.data.fuel-sales`
- `graphs.data.non-fuel-sales`
- `graphs.asset`

Then open `/graphs` while logged in.
