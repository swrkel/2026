**Helper file: `Modules/Petro/Services/SettlementPaymentReconciler.php`** — two-method API:

```php
<?php

namespace Modules\Petro\Services;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Support\Collection;
use Illuminate\Support\Facades\DB;
use Modules\Petro\Entities\SettlementCardPayment;
use Modules\Petro\Entities\SettlementCashPayment;
use Modules\Petro\Entities\SettlementChequePayment;
use Modules\Petro\Entities\SettlementCreditSalePayment;

class SettlementPaymentReconciler
{
    private const TABLE_TO_MODEL = [
        'settlement_card_payments'        => SettlementCardPayment::class,
        'settlement_cash_payments'        => SettlementCashPayment::class,
        'settlement_cheque_payments'      => SettlementChequePayment::class,
        'settlement_credit_sale_payments' => SettlementCreditSalePayment::class,
    ];

    /**
     * Incremental upsert by (business_id, settlement_no, pump_payment_id).
     * Used at every Step 3 call-site replacement of ::create().
     * Never deletes rows.
     */
    public function upsertOne(int $businessId, string $settlementNo, string $table, array $row): Model
    {
        $this->assertTable($table);
        $modelClass = self::TABLE_TO_MODEL[$table];

        return DB::transaction(function () use ($businessId, $settlementNo, $table, $row, $modelClass) {
            app()->instance('petro.reconciler.active', true);
            try {
                $pumpPaymentId = $row['pump_payment_id'] ?? null;

                // Orphan path — no source identity, always insert.
                if ($pumpPaymentId === null) {
                    return $modelClass::create(array_merge($row, [
                        'business_id'   => $businessId,
                        'settlement_no' => $settlementNo,
                    ]));
                }

                $existing = $modelClass::where('business_id', $businessId)
                    ->where('settlement_no', $settlementNo)
                    ->where('pump_payment_id', $pumpPaymentId)
                    ->first();

                if ($existing) {
                    $existing->fill(array_merge($row, [
                        'business_id'   => $businessId,
                        'settlement_no' => $settlementNo,
                    ]));
                    $existing->save();
                    return $existing;
                }

                return $modelClass::create(array_merge($row, [
                    'business_id'   => $businessId,
                    'settlement_no' => $settlementNo,
                ]));
            } finally {
                app()->forgetInstance('petro.reconciler.active');
            }
        });
    }

    /**
     * Full-set replacement. RESERVED — do not call from controllers in Step 3.
     * Inserts, updates, AND deletes to converge $table for ($businessId, $settlementNo)
     * to exactly the rows in $desiredRows (keyed by pump_payment_id).
     */
    public function reconcileSet(int $businessId, string $settlementNo, string $table, Collection $desiredRows): array
    {
        $this->assertTable($table);

        return DB::transaction(function () use ($businessId, $settlementNo, $table, $desiredRows) {
            app()->instance('petro.reconciler.active', true);
            try {
                $existing = DB::table($table)
                    ->where('business_id', $businessId)
                    ->where('settlement_no', $settlementNo)
                    ->whereNotNull('pump_payment_id')
                    ->get()
                    ->keyBy('pump_payment_id');

                $desired = $desiredRows
                    ->whereNotNull('pump_payment_id')
                    ->keyBy('pump_payment_id');

                $orphans = $desiredRows->whereNull('pump_payment_id');

                $toInsert = $desired->diffKeys($existing);
                $toUpdate = $desired->intersectByKeys($existing);
                $toDelete = $existing->diffKeys($desired);

                foreach ($toInsert as $row) {
                    DB::table($table)->insert(array_merge((array) $row, [
                        'business_id'   => $businessId,
                        'settlement_no' => $settlementNo,
                    ]));
                }
                foreach ($toUpdate as $pumpPaymentId => $row) {
                    DB::table($table)
                        ->where('business_id', $businessId)
                        ->where('settlement_no', $settlementNo)
                        ->where('pump_payment_id', $pumpPaymentId)
                        ->update((array) $row);
                }
                if ($toDelete->isNotEmpty()) {
                    DB::table($table)
                        ->where('business_id', $businessId)
                        ->where('settlement_no', $settlementNo)
                        ->whereIn('pump_payment_id', $toDelete->keys()->all())
                        ->delete();
                }
                foreach ($orphans as $row) {
                    DB::table($table)->insert(array_merge((array) $row, [
                        'business_id'   => $businessId,
                        'settlement_no' => $settlementNo,
                    ]));
                }

                return [
                    'inserted' => $toInsert->count(),
                    'updated'  => $toUpdate->count(),
                    'deleted'  => $toDelete->count(),
                    'orphans'  => $orphans->count(),
                ];
            } finally {
                app()->forgetInstance('petro.reconciler.active');
            }
        });
    }

    /**
     * Bypass helper for seeders and tests that need to write directly.
     * Releases the flag in a finally so it cannot leak on exception.
     */
    public static function withBypass(callable $cb)
    {
        app()->instance('petro.reconciler.active', true);
        try {
            return $cb();
        } finally {
            app()->forgetInstance('petro.reconciler.active');
        }
    }

    private function assertTable(string $table): void
    {
        if (! isset(self::TABLE_TO_MODEL[$table])) {
            throw new \InvalidArgumentException("SettlementPaymentReconciler does not handle table: {$table}");
        }
    }
```

```php
<?php

namespace Modules\Petro\Services;

use Illuminate\Support\Collection;
use Illuminate\Support\Facades\DB;

/**
 * Reconciles the four settlement_*_payments tables against the desired set of
 * pumper payments for a given settlement_no. Replaces the legacy wipe-and-reinsert
 * pattern that produced duplicate rows on every settlement edit.
 *
 * Public contract:
 *   reconcile(int $businessId, string $settlementNo, string $table,
 *             Collection $desiredRows): array
 *
 * $desiredRows: each item MUST contain 'pump_payment_id' (int) plus the full
 * column set for an insert into $table. Rows whose 'pump_payment_id' is NULL
 * are inserted unconditionally (provenance unknown) and logged.
 *
 * Returns: ['inserted' => N, 'updated' => N, 'deleted' => N, 'orphans' => N].
 */
class SettlementPaymentReconciler
{
    private const TABLES = [
        'settlement_card_payments',
        'settlement_cash_payments',
        'settlement_cheque_payments',
        'settlement_credit_sale_payments',
    ];

    public function reconcile(int $businessId, string $settlementNo, string $table, Collection $desiredRows): array
    {
        if (!in_array($table, self::TABLES, true)) {
            throw new \InvalidArgumentException("Unsupported table: {$table}");
        }

        return DB::transaction(function () use ($businessId, $settlementNo, $table, $desiredRows) {
            $existing = DB::table($table)
                ->where('business_id', $businessId)
                ->where('settlement_no', $settlementNo)
                ->whereNotNull('pump_payment_id')
                ->get()
                ->keyBy('pump_payment_id');

            $desired = $desiredRows
                ->whereNotNull('pump_payment_id')
                ->keyBy('pump_payment_id');

            $orphans = $desiredRows->whereNull('pump_payment_id');

            $toInsert = $desired->diffKeys($existing);
            $toUpdate = $desired->intersectByKeys($existing);
            $toDelete = $existing->diffKeys($desired);

            foreach ($toInsert as $row) {
                DB::table($table)->insert((array) $row);
            }
            foreach ($toUpdate as $pumpPaymentId => $row) {
                DB::table($table)
                    ->where('business_id', $businessId)
                    ->where('settlement_no', $settlementNo)
                    ->where('pump_payment_id', $pumpPaymentId)
                    ->update((array) $row);
            }
            if ($toDelete->isNotEmpty()) {
                DB::table($table)
                    ->where('business_id', $businessId)
                    ->where('settlement_no', $settlementNo)
                    ->whereIn('pump_payment_id', $toDelete->keys()->all())
                    ->delete();
            }
            foreach ($orphans as $row) {
                DB::table($table)->insert((array) $row);
            }

            return [
                'inserted' => $toInsert->count(),
                'updated'  => $toUpdate->count(),
                'deleted'  => $toDelete->count(),
                'orphans'  => $orphans->count(),
            ];
        });
    }
}
```

**Reconciler API — two methods, not one.** The earlier draft proposed a single `reconcile()` that takes a "desired set" collection and inserts/updates/deletes to converge to it. That contract is wrong for the per-call-site recipe: each site adds ONE payment at a time, not a complete settlement. Calling `reconcile($business, $settlement, $table, collect([$oneRow]))` in a loop would delete every other row for the same settlement on each iteration, because they would all be "absent from the desired set."

The Reconciler MUST expose two distinct methods:

```php
namespace Modules\Petro\Entities\Concerns;

trait RequiresReconcilerContext
{
    /**
     * Temporary allowlist of caller namespace prefixes. Each entry must list a
     * removal date and the doc that tracks the migration.
     *
     * DO NOT add to this list without updating PETRO_REFACTOR_WEEK1.md.
     */

        // SettlementSW — 15 ::create / new+save sites pending migration in week 1.
        // Remove this entry when PETRO_REFACTOR_WEEK1.md "SW migration" task is done.
        'Modules\\SettlementSW\\Http\\Controllers\\',
    ];

    protected static function bootRequiresReconcilerContext(): void
    {
        static::creating(function ($model) {
            if (app()->bound('petro.reconciler.active')) {
                return; // Reconciler-managed write — pass.
            }

            // Caller-namespace allowlist (temporary, week-1 removes).
            $caller = self::detectCallerNamespace();
            foreach (static::$reconcilerCallerAllowlist as $allowedPrefix) {
                if ($caller !== null && str_starts_with($caller, $allowedPrefix)) {
                    return; // SettlementSW or other temporary exception — pass.
                }
            }

            throw new \RuntimeException(
                static::class . " writes are restricted to SettlementPaymentReconciler. " .
                "Calling ::create() / new+save() directly is no longer permitted from " . ($caller ?? 'unknown caller') . ". " .
                "Route this write through Modules\\Petro\\Services\\SettlementPaymentReconciler::upsertOne()."
            );
        });

        // updating: intentionally NOT guarded today. fill()->save() on already-loaded rows
        // (e.g. AddPaymentController.php:384-385) is a legitimate edit pattern that must
        // continue to work until week 1 routes it through upsertOne().
    }

    private static function detectCallerNamespace(): ?string
    {
        foreach (debug_backtrace(DEBUG_BACKTRACE_IGNORE_ARGS, 20) as $frame) {
            $cls = $frame['class'] ?? null;
            if (! $cls) {
                continue;
            }
            // Skip Laravel/Illuminate internals and the model itself
            if (str_starts_with($cls, 'Illuminate\\') || str_starts_with($cls, 'Modules\\Petro\\Entities\\')) {
                continue;
            }
            return $cls;
        }
        return null;
    }
}
```

## What the tests will and will not catch (read this before declaring done)

**The combined coverage (8 characterization tests + Reconciler unit tests + 3 lock tests + DB UNIQUE + Eloquent guard + CI static check) WILL catch:**

- Duplicate row counts in `settlement_*_payments` after edit — `SettlementEditTest`, `NoDuplicateAccountingRowsAfterMultipleEditsTest`, and the DB unique constraint as the physical floor.
- `pump_payment_id` being populated on new inserts — `PumpPaymentIdPopulatedOnNewWritesTest`.
- Edit-one-affects-only-that-one semantics — `EditOneCreditSaleAffectsOnlyThatOneTest` (IS1293).
- Payment-to-Finalize totals being correct — `PaymentToFinalizeTotalsTest` (S 235/237/238/IS1216).
- Reconciler internal correctness — idempotency, insert/update/delete diff math.
- **Any future direct write to a settlement_*_payments table outside the Reconciler** — caught at three points: (a) Eloquent guard at runtime in dev/staging, (b) CI static check at merge time, (c) DB UNIQUE constraint at insert time if guard somehow disabled.
- The 5 specific HTTP flows we wrote tests for.

**They WILL NOT catch:**

- Bugs in flows we did not write tests for — the destroy path, VAT settlement (`VatSettlementController` — note this module uses its own `VatSettlement*Payment` models, NOT the four we are guarding, so VAT writes are untouched today), `OtherSale` / `OtherIncome` / `CustomerPayment` / `SettlementExpensePayment` / `SettlementExcessPayment` / `SettlementShortagePayment` tables, DailyVoucher edits independent of settlement, Pumper Dashboard's own list views.

Lock 2's namespace allowlist lets them keep working in production today, but they continue to produce duplicate rows in SW just as they did before this refactor. Week 1 migrates them through `upsertOne()` and removes the allowlist entry in the same PR.
- **Update-via-`fill()->save()` flows** at `AddPaymentController.php:384-385, 391-392, 574` and similar. Lock 2 is create-only today, so these continue to work; but they bypass the Reconciler's identity invariants. Week 1 routes them through `upsertOne()` (which performs an UPDATE when an existing row is found) and only then adds the `updating` guard.
- Edge cases not in our assertions: NULL `settlement_no`, `'ST5'` vs `'6'` overloaded values, negative amounts (excess), special characters in `collection_form_no`, multi-shift edits where the same operator has rows in two shifts simultaneously.
- Race conditions or two users editing the same settlement concurrently. The DB UNIQUE constraint partially mitigates this — concurrent inserts of the same key will have one win and one fail loudly rather than both silently succeed.
- Blade/view-layer bugs (totals computed in the template rather than the controller).
- Historical data corruption — we explicitly are not fixing the past.
- The ~20% of geetha complaints that are UI/business-rule bugs unrelated to payment identity.

3. Nightly monitoring query (defence layer 4) that runs for one week:
   ```sql
   SELECT 'settlement_card_payments' AS t, business_id, settlement_no, pump_payment_id, COUNT(*) AS c
   ```
